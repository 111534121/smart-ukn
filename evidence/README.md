## 缺口修復紀錄

### 1.（已修復）規章回答缺少「最後更新日期」（R3）
- **改了什麼**：`knowledge_base` 資料表新增 `updated_at` 欄位（`DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`，資料庫會自動維護，不用手動寫程式更新）；`/api/search`、`/api/rules` 的新增/修改都會帶上這個欄位；回應 JSON 新增 `last_updated`（格式 `YYYY-MM-DD`，由新增的 `format_updated_at()` 統一轉換 MySQL 物件與示範資料字串）。
- **複測結果**：搜尋「棄修」→ `last_updated: "2026-10-05"`，正確顯示。前端若要顯示，可直接讀取 `last_updated` 欄位加在規章卡片上（目前還沒接到前端畫面，只確認後端 API 已回傳正確值，前端顯示留給你們自行串接或我再接著做）。

### 2.（已修復）期限雷達沒有角色過濾，也沒有動態逾期標示（R4）
- **改了什麼**：
  - `/api/deadlines` GET 新增 `_deadline_visible_to_role()`，依登入角色過濾結果（`applies_to_role` 為 `all` 或包含該角色才顯示；未登入者只看得到 `all`）；`?role=` 參數現在只有管理員/教職員能用來預覽其他身分看到的內容，一般人無法靠改網址繞過。
  - 新增 `_compute_deadline_status()`，`status_badge`、`countdown_days`、`is_urgent` 全部改成讀取當下即時依「今天日期」計算，不再是建立資料時寫死的文字。
- **複測結果**：
  - 未登入呼叫 → 回傳空清單（目前種子資料裡沒有任何 `applies_to_role: "all"` 的公開項目，這是資料內容問題不是程式漏洞；只要未來新增一筆 `all` 的期限，未登入者就能正確看到它）。
  - `student1` 登入呼叫 → 正確只看到 4 筆屬於「學生」或「學生,老師,家長」的項目；截止日 2026-10-18 的項目，今天 (2026-10-05) 查詢正確顯示「進行中（剩 13 天）」，11/1 才開放的項目正確顯示「尚未開放（27 天後開始）」——不再是之前那個寫死、天數不會變的假資料。

### 3.（已修復）規章與期限的修改沒有留下紀錄（R5）
- **改了什麼**：新增 `audit_logs` 資料表（`table_name, record_id, action, changed_by, changed_by_role, before_json, after_json, changed_at`）；`write_audit_log()` 會在 DB 連得上時寫入資料庫，連不上則退回記憶體清單，兩種模式都能用；已掛在 `/api/rules`（新增/修改/刪除）、`/api/synonyms`（新增/刪除）、`/api/checklists`（新增）、`/api/deadlines`（新增）這些有寫入動作的 API 上；新增 `GET /api/admin/audit-logs`（僅管理員/教職員可查）；後台管理頁 `admin.html` 新增「修改歷程」分頁，可依資料表篩選查看。
- **複測結果**：以 `admin` 新增一筆測試規章 → 查詢 `/api/admin/audit-logs?table_name=knowledge_base` 正確出現一筆「新增」紀錄，含操作者「系統超級管理員 (管理員)」、修改後內容完整 JSON；再刪除該筆測試規章 → 正確新增第二筆「刪除」紀錄，含修改前內容。兩筆紀錄皆有正確時間戳記。

## 已通過但建議留意的項目

- R1、R2 的後端權限檢查確實是在伺服器端執行（不是只靠前端藏按鈕），這點做得不錯，驗收時可以直接展示：未登入打 API 回 401、家長查別人學號回 403。
- R3 測試途中發現一個**非系統本身的陷阱**：用 PowerShell 測試中文關鍵字時，如果沒有明確用 UTF-8 bytes 編碼，請求會變成亂碼導致搜尋失敗——這不是系統的 bug，是測試端的編碼問題，已在 test_record.md 裡註明並用正確編碼重測過。
- `/api/rules`、`/api/synonyms`、`/api/checklists` 目前仍是**純記憶體模式運作**（沒有實際呼叫資料庫讀寫，即使 MySQL 有連線也一樣），這是既有設計、不是這次改動造成的；也因此這幾支 API 的修改紀錄目前只會寫進 `audit_logs` 資料表（因為該表有走真正的 DB 連線），而不是寫進跟它一起改動的 `knowledge_base`/`synonym_dictionary` 本體。若未來要讓這些 CMS 功能真正持久化到資料庫，會是後續另一項工作。
- 「最後更新日期」目前只確認了**後端 API 正確回傳**，前台搜尋結果卡片還沒有加上顯示這一行文字，如果驗收也要看畫面顯示，請再跟我說一聲，我可以接著把前端補上。
- R4 的「未登入看不到任何期限」是因為目前種子資料沒有 `all` 類別的公開期限，建議驗收展示時换用 `student1` 登入後的畫面，比較看得出角色過濾有生效（而不是都看到空的，容易被誤會成功能沒做）。
