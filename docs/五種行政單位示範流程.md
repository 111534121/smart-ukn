# 五種行政單位示範流程

以下均為虛構資料與可編修的操作範例，不代表學校正式申辦規定。各案依承辦單位分流；承辦帳號只能辦理自己單位的案件。管理員可編修欄位、文件、期限與步驟。

| 單位 | 示範申請 | 學生填寫範例 | 承辦步驟 |
| --- | --- | --- | --- |
| 教務處／註冊組 | 在學證明申請範例 | 在學證明、校外實習用途、1 份、至註冊組領取 | 核對學籍與申請內容 → 製發及記錄交付 |
| 教務處／課務組 | 課程異動範例 | 115-1、CS101 計算機概論、資管五忠、課程時間調整諮詢 | 核對課程及班級 → 處理異動並回覆 |
| 總務處／事務組 | 教室設備報修範例 | 教學大樓 301 投影機無法顯示 | 確認故障與派工 → 記錄修繕及驗收 |
| 學生事務處／住宿管理 | 宿舍換房範例 | S305、換房、115 學年度第 1 學期、生活作息調整 | 核對住宿身分與床位條件 → 登記異動及通知 |
| 資訊管理科（五專）／科辦公室 | 科助證照資料收件範例 | 115-1 資訊證照影本 | 科助核對本科身分及缺件 → 確認收齊並回覆 |

這五種流程已列在行政案件工作台的申請類別中。宿舍設備報修也另有獨立範例流程。科助資料收件範例為每個科系各自建立；學生只能向所屬科系送件。

要在**示範資料環境**建立可操作案件，先停止服務，再於專案目錄執行 `python seed_admin_offices_demo.py`，之後重新啟動服務。此工具會建立標有「【處室示範】」的虛構案件；重跑不會覆寫已存在的同名案件。請先確認目前連到的是示範環境，避免把範例寫入正式資料。

示範登入帳號可從工作台的「切換示範身分」選取學生與各組承辦人。學生可送件與查看自己的進度；承辦人只能辦理所屬單位案件，跨單位須依轉交流程處理。

住宿管理統一使用 `dorm_demo`／`123456`，角色為「住宿管理員」，所屬單位固定為「學生事務處／住宿管理」。此帳號可在宿舍申請頁審核床位申請，也可在行政案件工作台處理住宿異動及設備報修；舊的 `demo_dorm` 不再列為示範登入帳號。既有 MySQL 環境須先執行 `python integration_schema.py` 更新角色欄位，再執行 `python seed_admin_offices_demo.py` 將示範帳號改為對應角色。

學生在「宿舍床位申請與送件進度」下方可直接進入「宿舍設備報修」或「入住／換房／退宿申請」，行政案件表單會預先選好對應類別；送件後從同一工作台查看處理進度。宿舍管理員審核床位申請時有獨立床號欄位，同學期同床號不能重複分配。

登入頁的「宿舍行政人員」快捷按鈕可填入測試帳號。登入後先顯示宿舍行政工作台，待辦只列宿舍申請及住宿行政案件；一般假單、證照、教室借用與導師關懷不屬於此帳號。從待辦進入行政案件時沿用同一瀏覽器分頁。

宿舍審核頁可按「編輯清冊」設定每學期的床號與房型。清冊設定後，分配的床號須在該學期清冊內；已分配的床位不能刪除，並會顯示占用狀態。床位排序階段可列入候補，日後再分配床位。床位清冊目前保存在本機示範資料中；跨伺服器部署前仍須搬到共用資料庫。候補次序與錄取規則須由校方確認。

一般假單、證照、教室借用的處室權限目前分別示範為生活輔導組、註冊組、事務組；各組帳號要先在行政工作台設定所屬處室。正式權責分工須由校方確認。行政案件在連接 MySQL 時使用共用資料表和版本檢查；部署既有資料時先執行 `python integration_schema.py` 搬移 JSON 紀錄。案件附件目前仍在伺服器本機檔案目錄，跨伺服器部署須配置共用附件儲存。

本機宿舍示範可用 `python seed_dorm_staff_demo.py` 建立，不會灌入其他處室案件：學生王小明有一筆待審床位申請，李美華有一筆已核對資格的進行中申請；行政案件包含待受理換房、處理中冷氣報修、待學生補件的退宿。全部標示「【宿舍示範】」，重跑不會複製同名案件。此工具只允許在未連接正式資料庫的示範模式執行。
