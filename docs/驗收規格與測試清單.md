# Smart UKN 軟體開發組驗收規格與測試清單

## 1. 專案定位

Smart UKN **不取代**康寧既有的成績、選課、請假、抵免與家長關懷系統；它提供跨系統的「規章解讀、個人影響判斷與下一步行動導航」。

## 2. 核心需求對照

| 編號 | 使用者與情境 | 系統功能 | 驗收結果 |
| --- | --- | --- | --- |
| R1 | 學生登入後發現某科不及格 | 顯示未通過科目、成績、必選修、擋修影響與重修建議 | 能區分「不及格」與「尚未修習」 |
| R2 | 家長想了解綁定子女的修課風險 | 僅顯示該子女的學分進度、不及格與擋修摘要 | 不可指定或查閱其他學生 |
| R3 | 學生詢問停修、抵免或請假 | 以口語搜尋規章，顯示官方名稱、來源、流程與既有系統入口 | 每個回答可追溯至規章資料 |
| R4 | 學生怕錯過行政期限 | 顯示個人化截止日、適用對象、待辦原因與官方入口 | 到期項目可排序，逾期項目清楚標示 |
| R5 | 行政人員更新規章或期限 | 維護規章、同義詞、流程、期限與版本紀錄 | 未授權者不得修改；每次修改有紀錄 |

## 3. 功能架構與資料流程

```text
學生／家長／教職員／管理員
        ↓ 登入與角色 Session
Smart UKN 前台
        ↓
Flask API
  ├─ 規章與同義詞檢索 → 規章內容、來源、行政流程
  ├─ 學分診斷 → 成績紀錄、課程地圖、先修規則、風險摘要
  ├─ 期限雷達（待完成）→ 行政期限、適用角色、官方系統連結
  └─ 後台 CMS → 規章／流程／期限／版本與修改紀錄
        ↓
MySQL；離線時以 Demo 資料展示
```

### 主要資料模型

- `users`：帳號、角色、綁定學號。
- `students`、`student_credits`：學生資料與成績紀錄。
- `course_map`：課程、學分、先修課關係。
- `knowledge_base`、`synonym_dictionary`、`checklist_items`：規章問答資料。
- `deadline_items`（待新增）：名稱、截止時間、適用角色、條件、官方入口、版本。
- `audit_logs`（待新增）：誰在何時修改何種資料、修改前後內容。

| 操作 | 訪客 | 學生 | 家長 | 教職員 | 管理員 |

## 5. 核心功能測試紀錄

每次驗收需截圖或錄影，並將結果填入 `evidence/` 資料夾。

| 功能 | 正常測試 | 異常／權限測試 | 預期結果 |
| --- | --- | --- | --- |
| R1 學分診斷 | `student1` 登入，查看未通過的程式設計（一） | 未登入呼叫 API | 顯示 55 分與擋修影響；未登入回傳 401 |
| R2 家長查詢 | `parent1` 查看王小明資料 | 加上其他 `student_id` 查詢 | 只可看到綁定子女；回傳 403 |
| R3 規章搜尋 | 搜尋「棄修」或「英文抵免」 | 空白關鍵字 | 顯示來源與流程；回傳 400 |
| R4 期限雷達 | 顯示適用學生的未到期事項 | 非適用角色或過期事項 | 不顯示無關項目；逾期清楚標示 |
| R5 CMS | 管理員新增或修改一筆規章／期限 | 學生嘗試呼叫修改 API | 資料更新並留紀錄；學生被拒絕 |

### 仍待留意的事項（非阻斷性）
1. 「最後更新日期」目前只有後端 API 回傳正確值，**前台搜尋結果卡片尚未顯示**這一行文字。
2. `/api/rules`、`/api/synonyms`、`/api/checklists` 本體資料仍是記憶體模式運作，尚未真正持久化到 MySQL（既有設計，非本次改動範圍）。
3. R4 未登入時目前會看到空清單，是因為種子資料剛好沒有 `applies_to_role: "all"` 的公開期限，屬資料內容而非程式邏輯問題。

詳細修復內容與複測證據見 `evidence/README.md`。

### 待補的真實資料

- 老師辦公室位置、晤談時間與分機；校園建築與教室配置（`campus/facilities.py`）。
- 下學期開課時段（`campus/courses_ext.py`）、每學期學分上下限（目前 12–28，請依學則確認）。
- 獎助學金項目與條件、學生負責的計畫經費（`campus/services.py`）。
- 學餐點餐、教科書訂購、Microsoft 365 校園授權網址（`links.json` 中標示 TODO 者）。
- 人流分析需接門禁、Wi-Fi 或學餐交易資料才會是真實數據。

## 8. 交付前檢查

- 核心流程可由登入一路操作到結果頁，不能只展示靜態畫面。
- 所有權限檢查由後端執行，不能只靠前端隱藏按鈕。
- 每個規章回答都能說明來源與最後更新日期。
- 每項核心功能至少有一筆正常測試與一筆異常／權限測試證據。
- 每一項未完成需求都寫明原因、影響與預計完成方式。
