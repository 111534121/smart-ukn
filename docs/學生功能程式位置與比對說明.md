# 學生功能：程式在哪裡、資料怎麼比對

> 2026-10-29 整理。每個功能列出「畫面在哪、程式在哪個檔案的哪個函式、用到哪些資料表、資料怎麼比對」。

## 怎麼在程式裡找到某個功能

程式碼裡每個功能用到的函式上方都有一行標記：

```python
# 【功能：重補修推薦】步驟 3：班別每個時段和學生自己的課表逐一比對，列出撞到哪門課
def find_conflicts(meetings, schedule):
```

在 VS Code 按 **Ctrl+Shift+F**，搜尋 `【功能：重補修推薦】`，就會列出這個功能用到的所有程式（後端 Python 與前端 JavaScript 都有標）。
只搜尋 `【功能：` 會列出全部有標記的功能。

所有功能的共同架構：

```
瀏覽器 (static/index.html + static/js/*.js)
   │  fetch('/api/...')
   ▼
Flask API (app.py 或各功能資料夾的 __init__.py / campus/*.py)
   │  比對邏輯 (盡量寫成不碰資料庫的純函式，例如 retake/logic.py)
   ▼
MySQL (連不上時改用示範資料：app.py 的 DEMO_*、dashboard/demo_data.py、data/campus_store.json)
```

## 1. AI 智慧校規查詢

**畫面**：首頁「AI 智慧校規查詢」，有三種模式。

| 模式 | 前端 | 後端 API | 函式 |
|---|---|---|---|
| 我知道要查什麼 (打字自動完成) | `static/js/campus-features.js` | `GET /api/campus/rules/suggest` | `campus/rules_ext.py` → `suggest()` |
| 我知道要查什麼 (按搜尋) | `static/index.html` → `handleSearch()` | `POST /api/search` | `app.py` → `search_knowledge()` |
| 我不確定，幫我問 | `campus-features.js` → `startGuide()` | `GET /api/campus/rules/candidates` | `campus/rules_ext.py` → `candidates()` |

**資料**：`knowledge_base` (規章)、`synonym_dictionary` (口語 → 正式名稱)、`checklist_items` (對應的申辦流程)。
題庫內容在 `campus/official_rules.py`，整理自官網法規 PDF，每題都附原文網址與頁碼；改完執行 `python tools/sync_official_rules.py` 寫進資料庫。

**比對方式**

- 自動完成 `suggest()`：開頭相同 3 分、包含 2 分、大部分字都有 1 分，取前 10 個。
- 搜尋 `search_knowledge()`：
  1. 先查同義詞表，把「棄修」換成正式名稱。
  2. 每條規章計分：關鍵字命中 100、正式名稱 90、原始輸入命中關鍵字 80、分類 50、內文 30。
  3. 取最高分，再用 `related_kb_id` 找對應的申辦流程。
- 幫我問 `candidates()`：
  1. 學生的句子拆成「每兩個字」的片段 (`_bigrams()`)：「多益要幾分」→ 多益、益要、要幾、幾分。
  2. 每條規章：句子裡出現它的口語詞 (例如「多益」) 直接 +20 分。
  3. 再加上兩字片段和規章名稱、分類、口語詞重疊的數量，和內文重疊的數量 × 0.3。
  4. 由高分到低分排，前端一題一題問「你是不是想問…」。

## 2. 重補修推薦

**畫面**：「重補修推薦」分頁。前端 `static/js/retake.js` → `loadRetake()`。
**API**：`GET /api/student/retake-recommendations` (`retake/__init__.py`)。
**資料**：`student_credits` (歷年成績)、`course_map` (課程)、`class_schedule` (本學期全校課表)。

**比對方式** (`retake/logic.py`，都是純函式，有 16 項測試 `tests/test_retake.py`)

1. `needs_retake()`：同一科修過多次，有一次及格就算通過；都沒過的才要重補修。
2. `sections_of()`：本學期還有哪些班開同一門課。課名先統一全形 / 半形括號與空白 (`normalize_name()`)。
3. `find_conflicts()`：班別的每個時段和學生自己的課表比對，`overlaps()` 判斷同一天且節次有交集就是衝堂。
   - `is_free_time()`：自己班課表上的「自習/班週會」不算衝堂，可以拿來重補修；週三下午的校部週會、社團活動照樣算衝堂。
4. `recommend()`：決定狀態 (已在課表 / 有班可選 / 全部衝堂 / 未開課)。不衝堂的班排前面，再比「要多到校幾天」，第一個標成推薦。

## 3. 修業進度與擋修、畢業進度

**畫面**：「修業進度與擋修」、「畢業進度」分頁。
**資料**：`student_credits`、`course_map` (含 `prerequisite_id` 先修科目)、證照紀錄。

| 步驟 | 位置 |
|---|---|
| 讀歷年成績 | `app.py` → `load_student_credits()` |
| 整理已通過 / 未通過 (修多次只要一次及格就算過) | `app.py` → `summarize_credits()` |
| 逐科比對先修科目：先修不在已通過清單 → 擋修 | `app.py` → `check_courses_prerequisites()` (`/api/courses/check`) |
| 已修學分、證照張數和門檻 (220 學分、2 張證照) 比，算還差多少 | `app.py` → `_compute_graduation_dashboard()` |

## 4. 缺曠扣考提醒

**畫面**：首頁的缺曠提醒、通知中心。
**位置**：`attendance/policy.py` → `summarize_attendance()`。
**資料**：缺曠紀錄 (`attendance_records`)、每科每週時數。

**比對方式**：每科缺曠時數和全學期時數比。

- 缺曠達全學期時數 1/3 就扣考；如果都是公假或重大傷病假，門檻是 1/2 (依專科班學則第 17 條)。
- 到門檻的 2/3 先標成「接近扣考」(warning)。
- 回傳剩幾小時到門檻。

## 5. 獎助學金資格比對

**畫面**：「獎助學金」分頁、通知中心。
**API**：`GET /api/scholarships/match` → `app.py` → `match_scholarships()`。

**比對方式** (`app.py` → `evaluate_scholarship()`)：每項獎學金的條件逐一比對學生資料。

| 條件 | 類型 |
|---|---|
| 年級、科系、身分別 | 硬性條件，不符 = 「不符合」 |
| GPA、操行成績、前學期無不及格 | 成績條件，只差這些 = 「部分符合」 |

全部條件都通過才是「符合」。截止日 7 天內標成緊急，通知中心會提醒。家長查看時，個人數值不顯示，只顯示符合或不符合。

## 6. 教師專長查詢

**畫面**：「教師專長查詢」分頁。前端 `static/js/faculty.js` → `searchFaculty()`。
**API**：`GET /api/faculty` → `faculty/__init__.py` → `search_faculty()`。
**資料**：`faculty_profiles` (專長)、`teacher_directory` (辦公室、照片)、`class_schedule` (授課)。

**比對方式** (`faculty/logic.py`)

1. `expand_terms()`：把學生的說法擴充成專長標籤的寫法 (例如 AI → 人工智慧、機器學習；資安 → 資訊安全)。
2. `score_profile()`：姓名 100、專長完全相同 60、部分相同 40、領域 30、授課課程 20、簡介 15 分；擴充出來的詞打 6 折。
3. 沒有專長資料、但在老師名錄或課表上的老師也會列出，可以用姓名或授課課程找到。

## 7. 老師辦公室與目前狀態、後台審核

**畫面**：「校園地圖與老師辦公室」分頁下方。前端 `static/js/campus-life.js` → `loadTeachers()`。後台在 `/admin` 的「老師辦公室與審核」(`static/admin.html`)。
**資料**：`teacher_directory`、`class_schedule`。

| 做什麼 | 位置 |
|---|---|
| 學生看得到的老師 = 已核准的名錄 + 課表上有課但還沒登錄的老師 | `campus/facilities.py` → `published_teachers()` |
| 現在時間比對課表與可以找老師的時間：上課中 / 可以找老師 / 沒有課 / 非上班時間 | `campus/facilities.py` → `teacher_status()` |
| 教職員修改已上線的資料：存進 `pending_data` 等審核，學生仍看到舊資料 | `campus/teacher_admin.py` → `update_teacher()` |
| 管理員核准或退回 | `campus/teacher_admin.py` → `review_teacher()` |
| 資料存取 (MySQL，沒有表時用 JSON) | `campus/teachers_store.py` |

科系、服務單位、姓名的篩選在瀏覽器端完成，不用再呼叫 API。

## 8. 表單下載與常用表單

**畫面**：任何頁面上方工具列的「📄 表單」，以及「行政申辦」分頁的「表單下載」。前端 `static/js/forms-finder.js`。
**API**：`GET /api/campus/forms`、`PUT /api/campus/forms/favorites` (`campus/services.py`)。
**資料**：`checklist_items` (有附表單的申辦流程)；常用表單存在 `user_preferences.favorite_forms`，每個帳號各自一份。

**比對方式** (`_form_matches()`)：在表單名稱、業務名稱、處室和口語關鍵字 (`FORM_KEYWORDS`，例如「英文、多益」對到外語證照免修表) 裡找查詢字。

- 兩個字以內要完全符合。
- 三個字以上，可以有一個字對不上。

## 9. 線上會議

**畫面**：「線上會議」分頁。前端 `static/js/meetings.js`。
**API**：`campus/meetings.py`。
**資料**：`meetings`、`meeting_members` (`campus/meetings_store.py`)。

| 做什麼 | 位置 |
|---|---|
| 誰可以邀請哪些班 (老師：自己任教與導師班；教職員、管理員：全部；學生：只能邀請個人) | `invitable_classes()` |
| 班級展開成學生名單，已在會議裡的人不重複加入 | `_invite()` |
| 只有主持人看得到邀請碼與成員名單 | `_describe()` |
| 邀請碼加入：比對 `invite_code`，檢查沒取消、沒結束、沒關閉邀請碼 | `join_by_code()` |
| 受邀的會議出現在通知中心 | `meetings.js` → `updateMeetingNotifications()`，以及 `static/index.html` → `buildNotifications()` 的「線上會議」段落 |

**視訊**：用 Jitsi Meet，會議室名稱是隨機字串，只有會議成員從系統拿得到連結。

- 預設在新分頁開 `meet.jit.si`。公開伺服器嵌在其他網站只能用 5 分鐘，開會的人也要登入。
- 學校架了自己的 Jitsi 伺服器時，設定 `.env` 的 `JITSI_DOMAIN=網域`、`JITSI_EMBED=1`，就會直接嵌在網站裡。

## 10. 通知中心

**位置**：`static/index.html` → `buildNotifications()`。

通知不另外存一張資料表，而是把各功能 API 回傳的資料轉成通知。包括：班級通知、作業、公告、請假結果、缺曠扣考、獎學金、會議邀請。
已讀狀態存在瀏覽器 (`localStorage`)，id 會帶狀態。例如作業從「快到期」變成「逾期」時 id 會改變，就會再提醒一次。
