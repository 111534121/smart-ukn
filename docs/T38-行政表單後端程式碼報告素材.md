# T38 行政表單後端程式碼報告素材

本文件提供實作位置與驗證事實，供報告撰寫者自行整理敘述。系統目前支援示範資料模式；實際校務資料、正式表單與承辦權責仍須由學校確認。

## 可示範的流程

1. 學生登入後在首頁開啟申辦項目，線上填寫欄位並送出。必填欄位、欄位長度及同一項目審核中的重複申請由後端檢查。
2. 老師或教職員看到所屬關卡的待審案件，依順序核准或填原因退回；後端檢查角色、導師班級及目前關卡，避免越權或重複簽核。
3. 學生可看申辦進度和簽核歷程。表單頁可看空白版、填寫範例，並下載對應 Word 檔；線上填寫視窗也有範例下載入口。
4. 後台「修改紀錄」可選「線上申辦」，查看申請新增及簽核修改的操作人、角色、時間和變更內容；API 另支援以案件編號 `record_id` 精確查詢。

## 後端程式位置

- `applications/__init__.py`：`GET /api/applications/form/<item_id>` 提供欄位與簽核關卡；`POST /api/applications` 建立申請；`POST /api/applications/<id>/review` 處理簽核；`GET /api/applications/mine` 與 `GET /api/applications/review` 提供進度和待審清單；`GET /forms/<code>` 提供空白或範例表單與 Word 下載。
- `applications/forms.py`：各表單欄位、填寫範例及關卡設定。
- `applications/templates/application_form.html`：可列印的表單與 Word 內容版型。
- `app.py`：`write_audit_log` 記錄操作；`GET /api/admin/audit-logs` 依表名及案件編號查詢，最多回傳最近 200 筆符合條件的紀錄。
- `campus/admin_cases.py`：處室通用行政案件的建立、審核及歷程，屬於另一組行政工作台流程。

## 前端入口

- `static/js/applications.js`：學生線上填寫、範例下載、進度檢視及老師簽核介面。
- `static/admin.html`：「修改紀錄」中的「線上申辦」篩選。
- `static/admin-workbench.html`、`static/js/admin-workbench.js`：處室通用行政案件工作台。

## 驗證與報告限制

## 可供本人改寫的程式解說

「學生送件時，`submit_application` 先從登入工作階段取得學生身分，再依 `applications/forms.py` 的設定驗證欄位與審核關卡；不是由前端自行指定學生或核准結果。資料寫入 `online_applications`，包含目前關卡、狀態與歷程。簽核時 `review_application` 透過 `can_review` 檢查登入角色、導師班級及目前關卡，再由 `save_transition` 以預期關卡更新，避免重複操作直接跳關。學生使用自己的進度查詢入口；老師只能處理授權班級，行政端依其可辦理流程操作。」

「操行功能將紀錄、評分與設定分別存入 `conduct_records`、`conduct_evaluations`、`conduct_settings`。驗收時分別以學生、導師及行政帳號確認本人、導師班與跨班查詢權限。資料庫升級使用 `applications_conduct_schema.py`，只補缺少的表，不執行會重建示範資料的初始化程式。」

本人報告時可示範：學生填表 → 導師逐關簽核 → 行政核備 → 學生查看結果 → 查詢同一案件的稽核紀錄。再以另一班學生示範權限拒絕，並開啟 Word 範例說明欄位來源。以上是報告素材，仍須由張晴茹閱讀、改寫與實際口頭說明；不能據此聲稱本人報告已完成。
