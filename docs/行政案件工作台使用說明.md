# 行政案件工作台

入口：登入後開啟 `/admin-workbench`，或從教職員首頁「行政人員工作台」、管理後台頁首、宿舍與總務申請頁的「行政申請與補件」進入。新增後端功能後須重新啟動原本的 Flask 服務。

## 管理員：先設定處室

以管理員登入，在「處室分工設定」替現有行政帳號選擇教務處、學務處、總務處、研發處或秘書室，按「儲存處室分工」。管理員可以查看全部案件；教職員只看所屬處室。未指定處室者不能讀取案件。老師、家長、訪客無法使用此工作台。

未連接資料庫的示範模式中，`staff1` 預設教務處；連接資料庫時，初次使用應由管理員設定實際行政帳號的處室。處室與科系是不同的資料，不以科系代替行政處室。

## 學生：送出與補件

1. 選擇申請類別，填入標題、說明與選填附件。
2. 系統依類別分流到對應處室，案件列為「待受理」。
3. 承辦人要求補件後，案件顯示「待補件」，可查看原因、資料清單與期限。
4. 補齊要求的資料，逐項勾選確認、填寫補件說明、上傳補交附件，按「補件完成，重新送審」。
5. 案件改為「重新送審」，由承辦處室再次受理。原始資料、每次補件與辦理紀錄均保留。

附件每次最多 5 個，每個 10 MB；支援 PDF、PNG、JPG、JPEG、DOCX、XLSX、TXT。附件只能透過登入且有案件權限的下載端點取得，不放在公開的 static 目錄。管理員亦可下載。

## 行政人員：分派、受理與結案

- 依標題、學號、編號搜尋，或篩選狀態、處室、自己承辦與逾期案件。
- 「分派／轉交」可交給其他處室，必須填寫交接說明。選承辦人時僅能指定目標處室的有效行政帳號；一般行政人員跨處室轉交可先交由對方處室分派。
- 轉交後原處室立即失去案件與附件權限；管理員仍可查看全部紀錄。
- 「受理並由我承辦」將待受理或重新送審案件改為「處理中」。
- 「要求補件」須填寫原因、1 至 15 項資料與補件期限；日期不可早於臺北當天日期。
- 「完成結案」與「退件結案」須先受理並填寫結果。結案後禁止再修改。
- 案件有版本檢查；多人同時辦理時，舊畫面無法覆寫新紀錄，須重新整理。
- 行政首頁與待辦鈴鐺會顯示該處室待受理、處理中、重新送審的行政案件。學生在工作台查看補件與結果，本次未新增 Email 或簡訊通知。

## 與原有業務的範圍

此版本處理從工作台新送出的行政申請。原有請假、證照、宿舍、教室借用、報帳繼續使用原本流程，工作台提供快捷入口；不會自動把既有申請複製成新案件。

目前案件與處室設定沿用 campus 的 `data/campus_store.json`；私有附件放在同層 `admin_case_files`。設定 `CAMPUS_DATA_DIR` 可改儲存位置，備份時應包含兩者。此版本未新增 MySQL 案件資料表；多程序部署前需將此儲存層改為共享資料庫交易。

## 驗收方式

新增 `tests/test_admin_cases.py`，驗證送件、跨處室轉派、補件附件、重新送審、受理結案、權限撤銷、私有附件、版本衝突與結案不可修改；同步補齊 `tests/permission_matrix.csv` 與功能對照說明。

瀏覽器另以獨立資料目錄實際走完：學生送件 → 教務處轉交總務處 → 總務處受理並要求兩項補件 → 學生勾選與填寫補件說明 → 重新送審 → 總務處再次受理並完成結案。

執行自動測試：`python -m pytest -q --basetemp=.pytest-tmp-admin-validation`。測試使用隔離資料，不寫入正式校務資料庫。
