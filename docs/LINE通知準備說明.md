# LINE 通知準備狀態

目前預設**不會發送 LINE 訊息**。已建立老師個人的通知選項儲存與事件去重基礎；選項為待審假單與關懷追蹤到期，預設皆關閉。`GET/PUT /api/line/settings` 僅供登入老師管理自己的選項，回傳 `active: false`。尚未提供畫面上的綁定入口，避免讓使用者以為正式通知已啟用。

## 專題測試帳號

可以使用自己建立的 LINE 官方帳號測試，不需動用學校的正式帳號。建立官方帳號並啟用 Messaging API 後，在伺服器環境變數設定 `LINE_DEMO_ENABLED=1`、`LINE_DEMO_USERNAME=teacher1`、`LINE_DEMO_USER_ID` 與 `LINE_CHANNEL_ACCESS_TOKEN`。`LINE_DEMO_USER_ID` 是 LINE Developers Console 的 **Your user ID**（須由已連結 LINE 的開發者帳號查看），不是官方帳號的 ID。先用自己的 LINE 加入測試官方帳號好友。

設定完成後，以指定的老師帳號登入，首頁會出現「LINE 專題測試」按鈕。按鈕只會手動送出一則明確標示為假資料的訊息到指定測試者；每分鐘最多一則，不會根據真實假單或關懷紀錄自動發送。LINE API 接受請求不等於手機必定收到；若未加好友或封鎖帳號，可能無法收訊。

正式啟用前仍需：

1. 學校建立並管理 LINE 官方帳號與 Messaging API channel，確認發送方案。
2. 建立經 LINE 驗證的帳號綁定流程，讓本人同意接收並可隨時解除；不可由瀏覽器自行提交 LINE user ID。
3. 加入發送工作、失敗重試與投遞狀態紀錄，再將設定畫面開放給老師。通知只包含事件摘要和官網連結；假單理由、關懷內容留在需登入的官網。
4. 用測試帳號驗證新增事件只送一次、錯誤接收者不會收到、解除綁定後停止發送。完成後才把 `active` 改成實際狀態。

正式環境的 LINE 憑證只放在伺服器環境變數，不能寫入原始碼或前端。現有「分享到 LINE」是使用者主動分享連結，不是自動通知。
