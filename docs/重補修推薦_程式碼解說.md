# 重補修推薦：比對流程與程式碼解說

## 一、整體流程

```
歷年成績 student_credits ─┐
課程地圖 course_map ──────┼─> needs_retake()  需要重補修的科目
                          │
當學期課表 class_schedule ┼─> my_schedule()   學生既有課表 (本班 + 個人加選)
                          └─> sections_of()   每科有哪些班別開課
                                   │
                                   ▼
                              recommend()     每個班別比對衝堂 → 判斷狀態、排序、寫說明
                                   │
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
     GET /api/student/retake-recommendations   build_notifications()
     (學生端畫面 retake.js)                    (交給通知中心)
```

| 檔案 | 內容 |
|---|---|
| `retake/logic.py` | 比對邏輯，全部是純函式 (不碰資料庫、Flask)，所以可以直接寫測試 |
| `retake/__init__.py` | API 路由、權限檢查、`notifications_for()` |
| `app.py` (`retake.init_app`) | 把資料庫讀取函式交給 retake 套件 |
| `static/js/retake.js` | 學生端畫面、通知連結定位 |
| `tests/test_retake.py` | 15 個測試 |

## 二、每個函式在做什麼

### 1. `needs_retake(credit_records, courses)`：找出要重補修的科目

- 成績依學期排序，同一科修過多次時，**只要有一次及格就算通過**。
- 都沒過的才列出來，分數、學期取最近一次。
- 順便從課程地圖找「這科沒過會擋到哪些課」(`prerequisite_id`)，畫面上會提醒擋修。

### 2. `my_schedule()`：學生的既有課表

課表裡有兩種列：
- `class_name` 有值：整班的課
- `student_id` 有值：個人加選 (例如已經加選的重修課)

學生的課表 = 本班的課 + 自己加選的課，兩種都要拿來比對衝堂。

### 3. `sections_of()`：同一科有哪些班別

- 課表沒有課程代碼，只有課名，所以用 `normalize_name()` 把全形括號換成半形、拿掉空白，「程式設計 (一)」和「程式設計(一)」才會被當成同一門課。
- 依班級分組：一門課可能一週上兩天，所以**一個班別可以有多個時段**。
- 個人加選的列不算開課班別，學生自己的班也排除 (要補修就得選其他班)。

### 4. `overlaps()` / `find_conflicts()`：衝堂判斷

```python
a["weekday"] == b["weekday"] and a["period_start"] <= b["period_end"] and b["period_start"] <= a["period_end"]
```

同一天，而且兩段節次有交集就算衝堂。例如「第 3-5 節」和「第 5-6 節」撞在第 5 節，「第 3-5 節」和「第 6-7 節」不衝堂。

班別的**每一個時段**都要跟課表比，只要有一個時段撞到，整個班別就不能選。撞到的課會記下「撞到哪門課、在哪一節」，讓學生知道原因。

### 5. `recommend()`：判斷狀態、排序

每一科會是以下四種狀態之一：

| 狀態 | 條件 | 給學生的說明 |
|---|---|---|
| 已在你的課表 `arranged` | 學生課表裡已經有這門課 | 已經在課表裡 (列出時間)，記得按時上課 |
| 有班別可選 `available` | 至少一個班別不衝堂 | 有幾個班不衝堂、推薦哪一班、另有幾班衝堂 |
| 全部衝堂 `all_conflict` | 有開課但每班都衝堂 | 有幾班開課但都衝堂，建議洽課務組或改暑修 |
| 本學期未開課 `not_offered` | 沒有其他班開這門課 | 留意下學期、暑修或洽課務組 |

**同科多個班別的排序**：
1. 不衝堂的排前面
2. 再來比「要多到校幾天」：那天學生本來就有課的優先，不用多跑一趟
3. 最後依星期、節次

排第一的不衝堂班別標成「推薦」。

**科目之間的排序**：全部衝堂 → 有班別可選 → 未開課 → 已在課表，也就是需要學生處理的排前面；同狀態下必修排在選修前面。

### 6. `build_notifications()`：通知資料

- 已在課表的科目不通知，其他三種狀態每科一則。
- `key` = `retake:學號:課程代碼:狀態`，通知中心拿來去重；狀態改變時 key 也會變，就可以再通知一次。
- `link` = `/?retake=課程代碼#retake`，點進去會開到重補修分頁，並捲到那門課 (`retake.js` 的 `rtFocusFromLink()`)。
- 串接方式寫在 [重補修推薦_通知串接說明.md](重補修推薦_通知串接說明.md)。

## 三、權限

- 只有學生本人和家長能看；學號**一律取自登入的 session**，網址上帶 `?student_id=` 也沒有用，所以看不到別人的資料。
- 未登入回 401，老師等其他身分回 403。
